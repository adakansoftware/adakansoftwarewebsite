# UI-preserving security hardening

## Goal

Harden server-side behavior and deployment configuration without changing visitor or admin UI.

## Scope

- Keep all existing screens, copy, navigation, and styling unchanged.
- Treat invalid or incomplete security-critical production configuration as unavailable for the affected sensitive operation.
- Retain public routes only where their data is intentionally public; keep API responses non-cacheable.

## Security design

### Browser boundary

- Replace the static production CSP with a per-request nonce CSP generated by `proxy.ts`, following the installed Next.js 16 guidance.
- Keep the policy self-only by default, permit only the currently required Vercel analytics connections, and retain explicit anti-framing, form-action, base-uri, object, worker, and mixed-content controls.
- Upgrade HSTS to include subdomains and preload eligibility. Preserve existing `nosniff`, referrer, permissions, COOP, and CORP protections.

### API boundary

- Apply explicit method responses consistently where an endpoint currently exposes an unintended default behavior.
- Ensure production-only credentials and signed request protections fail closed when their state-store or cryptographic configuration is unavailable.
- Continue using bounded request parsing and same-origin checks for state-changing browser requests.
- Keep route-level authorization authoritative; proxy rate limiting remains an opportunistic first layer only.

### Operational endpoints

- Do not broaden diagnostics or health output. Authorized diagnostics remain protected by signed administration requests.
- Harden replay/cron paths against malformed request metadata and failure in the backing state store, returning controlled errors rather than leaking implementation failures.

## Verification

- Add focused regression tests before each behavior change and observe them fail before the implementation.
- Run focused security tests, TypeScript checking, linting, production dependency audit, build, and the existing route smoke suite.

## Out of scope

- Visual or UX changes.
- Changing external Vercel, DNS, Redis, Neon, or secret-manager settings; deployment-side secrets must be set by the operator.
- Replacing the existing bespoke admin session system with a third-party identity provider.
